# PokePlanner

**Финальный проект по Android-разработке**

## Описание проекта

PokePlanner — мобильное Android-приложение для просмотра каталога Pokémon и ведения личных коллекций. Данные о Pokémon поступают из открытого API PokéAPI, а пользовательские записи, коллекции и история просмотров сохраняются локально. Основные персональные функции доступны без подключения к интернету.

## Используемые технологии

- **Kotlin** — язык разработки.
- **Jetpack Compose и Material 3** — пользовательский интерфейс.
- **Navigation Compose** — переходы между экранами.
- **Retrofit** — взаимодействие с PokéAPI.
- **Hilt** — внедрение зависимостей.
- **Room** — локальное хранение каталога, пользовательских записей, коллекций и истории.
- **DataStore** — сохранение настроек.
- **Coroutines, Flow, StateFlow и SharedFlow** — асинхронная обработка и реактивное обновление интерфейса.
- **WorkManager** — периодическое фоновое обновление локального каталога.

## Функциональные возможности

### Каталог и карточки Pokémon

Каталог отображает Pokémon, загруженных из PokéAPI. Предусмотрены поиск по английским названиям и номерам Pokémon во всём загруженном индексе и просмотр карточки выбранного Pokémon. Сетевые данные сохраняются в Room и повторно используются при отсутствии соединения.

### Личные записи и статусы

Для каждого Pokémon можно сохранить заметку и один из статусов: «В планах», «Тренирую» или «Готов». Записи доступны после повторного открытия приложения. Статусы также используются при фильтрации каталога.

### Пользовательские коллекции

В приложении реализовано создание, переименование и удаление коллекций с названиями и описаниями. Pokémon можно добавлять в несколько коллекций и исключать из них. Связи между коллекциями и Pokémon сохраняются в локальной базе данных.

### История просмотров

После успешной загрузки карточки Pokémon фиксируется запись в истории. Раздел «История» содержит ранее просмотренные элементы с переходом к их карточкам. Предусмотрена очистка истории.

### Настройки

Настройки включают выбор светлой или тёмной темы, фильтр запланированных Pokémon и срок актуальности кэша (6, 12 или 24 часа). Значения сохраняются в DataStore.

## Локальная модель данных

В Room предусмотрены таблицы `pokemon`, `personal`, `recent`, `collections`, `collection_members`, `catalog_index` и `sync_metadata`. Таблица `personal` содержит заметки и статусы; `collections` — пользовательские коллекции; `collection_members` — связи между коллекциями и Pokémon; `catalog_index` — индекс имён и идентификаторов; `sync_metadata` — время последней завершённой синхронизации. Для обновления схемы базы данных предусмотрены миграции с версий 1 и 2 до версии 3 с сохранением пользовательских данных.

## Offline-first и синхронизация

Локальная база Room является источником данных для пользовательского интерфейса. После первоначального получения данных из PokéAPI индекс каталога, история, заметки и коллекции остаются доступными без сети. Первые 60 карточек предзагружаются вместе с изображениями; остальные сохраняются при первом открытии с подключением к интернету. Успешно сохранённые карточки и изображения доступны офлайн. Сетевые запросы обновляют локальный кэш, не заменяя локальное хранение пользовательских записей.

Для каталога предусмотрена проверка срока актуальности данных (TTL). Фоновая задача `SyncWorker` реализована через WorkManager и выполняет обновление кэша при наличии сетевого подключения. Интервал задачи соответствует выбранному TTL; в открытом приложении актуальность кэша проверяется каждую минуту. В случае ошибки задача возвращает результат для повторной попытки.

## Реактивное обновление интерфейса

Состояние каталога формируется на основе нескольких источников: индекса и карточек Pokémon из Room, пользовательских данных, поискового запроса, настроек DataStore и состояния синхронизации. Для обработки потоков применяются `combine`, `debounce`, `distinctUntilChanged` и `stateIn`. Изменения локальных данных и настроек отражаются в интерфейсе без ручного перечитывания базы.

## Реализованные пользовательские сценарии

1. **Ведение личных записей:** выбор Pokémon, назначение статуса, сохранение заметки, последующее изменение или удаление записи.
2. **Управление коллекциями:** создание коллекции, редактирование её названия и описания, добавление и исключение Pokémon, удаление коллекции вместе с её связями.
3. **История просмотров:** автоматическое сохранение просмотренных Pokémon, повторное открытие карточек из истории и очистка истории.

## Тестирование

В проект включены 26 локальных unit-тестов и 16 инструментальных тестов. Unit-тесты проверяют загрузку и частичные ошибки, TTL, ограничение параллельных запросов, фильтрацию, восстановление состояния, последовательности Flow, повторные попытки и работу с коллекциями. Инструментальные тесты проверяют Repository с Room, миграции базы, сохранение изображений, запуск задач через WorkManager и пользовательские сценарии интерфейса.

## Источник данных

**PokéAPI:** https://pokeapi.co/api/v2/

API предоставляет сведения о Pokémon, включая названия, типы и изображения. Авторизация и API-ключ не требуются. Названия Pokémon и поиск по каталогу сохранены на английском языке; пользовательские заметки и названия коллекций поддерживают кириллицу.

## Исправления после проверки

- Код Kotlin, Gradle и манифест приведены к единому оформлению с отступами и переносами строк.
- Экраны, ViewModel, сущности Room, DAO и база данных разделены по отдельным файлам. В `AppNav` осталась навигация.
- Индексный `combine` с приведениями типов заменён типизированным объединением потоков. Неиспользуемый поток участников коллекций исключён из состояния каталога.
- Правила фильтрации, проверки названий и срока кэша используются в рабочем коде. Формальные проверки стандартных функций Kotlin заменены тестами поведения приложения.
- Число одновременных загрузок карточек ограничено четырьмя. Частичная загрузка сопровождается ошибкой и не считается завершённым обновлением кэша.
- Поиск работает по полному индексу Pokémon, включая элементы за пределами первых 60 карточек.
- Стандартный инициализатор WorkManager отключён в манифесте. Создание `SyncWorker` выполняется через `HiltWorkerFactory` и проверяется запуском задачи через WorkManager.
- История пополняется после успешной загрузки карточки. Ошибки отображаются на экране с возможностью повторной попытки.
- Текст поисковой строки и фильтрация используют единое состояние в `SavedStateHandle`.
- Создание и редактирование коллекций вынесены в отдельный диалог. Черновик и режим редактирования восстанавливаются после пересоздания экрана. Повторное сохранение во время выполнения операции заблокировано.
- Удаление коллекции требует подтверждения. Отмена сохраняет коллекцию, а подтверждённое удаление не затрагивает личные записи Pokémon.
- Строковое поле команды удалено из личных записей. Его прежние значения перенесены миграцией в коллекции и связи между сущностями.
- Статусы объединены в модель `PokemonStatus` с конвертером Room.
- Изображения сохраняются в постоянной папке приложения и отображаются из локальных файлов. При отсутствии спрайта в API используется локальная заглушка.
- Периодичность фонового обновления соответствует выбранному TTL. В открытом приложении выполняется автоматическая проверка актуальности данных.
- Открытие сохранённой карточки и восстановление изображения не перезаписывают метаданные, обновлённые фоновой синхронизацией. Сохранение заметки не скрывает ошибку загрузки изображения.
- Тесты дополнены проверками реальной логики Repository и ViewModel, последовательностей Flow, миграций, офлайн-режима, пользовательских сценариев и фоновых задач.
