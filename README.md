# PokePlanner

**Финальный проект по Android-разработке**

## Описание проекта

PokePlanner — мобильное Android-приложение для просмотра каталога Pokémon и ведения личных коллекций. Данные о Pokémon поступают из открытого API PokéAPI, а пользовательские записи, коллекции и история просмотров сохраняются локально. Основные персональные функции доступны без подключения к интернету.

## Используемые технологии

- **Kotlin** — язык разработки.
- **Jetpack Compose и Material 3** — пользовательский интерфейс.
- **Navigation Compose** — переходы между экранами.
- **Retrofit** — взаимодействие с PokéAPI.
- **Hilt** — внедрение зависимостей.
- **Room** — локальное хранение каталога, пользовательских записей, коллекций и истории.
- **DataStore** — сохранение настроек.
- **Coroutines, Flow, StateFlow и SharedFlow** — асинхронная обработка и реактивное обновление интерфейса.
- **WorkManager** — периодическое фоновое обновление локального каталога.

## Функциональные возможности

### Каталог и карточки Pokémon

Каталог отображает Pokémon, загруженных из PokéAPI. Предусмотрены поиск по английским названиям и просмотр карточки выбранного Pokémon. Сетевые данные сохраняются в Room и повторно используются при отсутствии соединения.

### Личные записи и статусы

Для каждого Pokémon можно сохранить заметку, название команды и один из статусов: «В планах», «Тренирую» или «Готов». Записи доступны после повторного открытия приложения. Статусы также используются при фильтрации каталога.

### Пользовательские коллекции

В приложении реализовано создание, переименование и удаление коллекций с названиями и описаниями. Pokémon можно добавлять в несколько коллекций и исключать из них. Связи между коллекциями и Pokémon сохраняются в локальной базе данных.

### История просмотров

При открытии карточки Pokémon фиксируется запись в истории. Раздел «История» содержит ранее просмотренные элементы с переходом к их карточкам. Предусмотрена очистка истории.

### Настройки

Настройки включают выбор светлой или тёмной темы, фильтр запланированных Pokémon и срок актуальности кэша (6, 12 или 24 часа). Значения сохраняются в DataStore.

## Локальная модель данных

В Room предусмотрены таблицы `pokemon`, `personal`, `recent`, `collections` и `collection_members`. Таблица `personal` содержит заметки, статусы и названия команд; `collections` — пользовательские коллекции; `collection_members` — связи между коллекциями и Pokémon. Для обновления схемы базы данных с версии 1 до версии 2 предусмотрена миграция.

## Offline-first и синхронизация

Локальная база Room является источником данных для пользовательского интерфейса. После первоначального получения данных из PokéAPI каталог, история, заметки и коллекции остаются доступными без сети. Сетевые запросы обновляют локальный кэш, не заменяя локальное хранение пользовательских записей.

Для каталога предусмотрена проверка срока актуальности данных (TTL). Фоновая задача `SyncWorker` реализована через WorkManager и выполняет обновление кэша при наличии сетевого подключения. В случае ошибки задача возвращает результат для повторной попытки.

## Реактивное обновление интерфейса

Состояние каталога формируется на основе нескольких источников: записей Pokémon из Room, пользовательских данных, связей коллекций, поискового запроса и настроек DataStore. Для обработки потоков применяются `combine`, `debounce`, `distinctUntilChanged` и `stateIn`. Изменения локальных данных и настроек отражаются в интерфейсе без ручного перечитывания базы.

## Реализованные пользовательские сценарии

1. **Ведение личных записей:** выбор Pokémon, назначение статуса, сохранение заметки и названия команды, последующее изменение или удаление записи.
2. **Управление коллекциями:** создание коллекции, редактирование её названия и описания, добавление и исключение Pokémon, удаление коллекции вместе с её связями.
3. **История просмотров:** автоматическое сохранение просмотренных Pokémon, повторное открытие карточек из истории и очистка истории.

## Тестирование

В проект включены 15 локальных unit-тестов и 6 инструментальных интеграционных тестов Room. Unit-тесты проверяют правила коллекций, фильтрацию, проверку названий, обработку идентификаторов и определение устаревшего кэша. Интеграционные тесты проверяют сохранение и чтение данных, отсутствие дублирования записей, порядок истории, добавление Pokémon в коллекцию и каскадное удаление связей.

## Источник данных

**PokéAPI:** https://pokeapi.co/api/v2/  
API предоставляет сведения о Pokémon, включая названия, типы и изображения. Авторизация и API-ключ не требуются. Названия Pokémon и поиск по каталогу сохранены на английском языке; пользовательские заметки и названия коллекций поддерживают кириллицу.
